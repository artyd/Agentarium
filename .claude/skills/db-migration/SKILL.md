# Author an Agentarium DB migration (no local DB)

There is no local Postgres, so migrations are generated by diffing schema snapshots. Prod/CI applies them with `prisma migrate deploy`.

## Steps
```bash
cd server
cp prisma/schema.prisma prisma/schema_old.prisma      # snapshot BEFORE editing
# --- now edit prisma/schema.prisma with the new models/fields ---
mkdir -p prisma/migrations/000N_name                  # next sequential prefix
npx prisma migrate diff \
  --from-schema-datamodel prisma/schema_old.prisma \
  --to-schema-datamodel prisma/schema.prisma \
  --script > prisma/migrations/000N_name/migration.sql
npx prisma generate                                   # refresh the client
rm prisma/schema_old.prisma
```

## Rules
- Keep the numeric prefix in sequence — existing: `0001_init`, `0002_features`, `0003_social`.
- Review the generated SQL before committing (destructive changes, defaults for NOT NULL columns on existing rows).
- After the schema change, update `src/lib/serialize.ts` and `web/src/api/types.ts` to match (see the `add-feature` skill).
- Do NOT run `prisma migrate dev` (it needs a live DB). Deploy applies the migration automatically.
